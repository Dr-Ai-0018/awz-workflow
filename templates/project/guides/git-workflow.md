# Git 工作流指南

## 分支

- 默认分支为 `main`。
- 小任务可以直接在当前工作分支完成。
- 中大型阶段、跨模块改动、多 Agent 协作、风险较高的 refactor，优先使用短生命周期 topic branch。
- topic branch 完成后合并回 `main`，不要长期漂着。

## Commit

禁止 AI attribution：

- 不写 `Co-authored-by: Codex`；
- 不写 `Co-authored-by: Claude`；
- 不写 `Generated by AI`；
- 不写 `Authored by Codex`；
- 不写 `Authored by Claude`。

使用环境中配置好的 git 用户名和邮箱。

commit subject：

```text
type: 中文一句话概括
```

commit body：

```text
1. **重点关键词**：具体改动点
2. **重点关键词**：具体改动点
```

## 节奏

- 一个 commit 对应一个可解释的 logical change；
- 不要一个字符级小改就提交一次；
- 不要把不相关文件和多个主题塞进同一个 commit；
- 阶段性工作可以拆成骨架、核心实现、测试验证、文档/清理；
- 大版本更新用 milestone、release checklist 或 tag 标注，不靠超大 commit 承载全部语义。
